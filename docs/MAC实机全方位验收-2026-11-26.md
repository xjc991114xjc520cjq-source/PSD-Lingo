## 实际发现与修复

1. Mac 更新此前直接禁用。新增 darwin/arm64 专用 ES256 清单、固定独立 feed、完整 PKG 下载与安装器交接。保留强制更新、跳过/稍后、离线缓存及单调策略序号；Mac 不使用 Windows 的 resources/app 原位替换。
2. 字体任务只接受盘符/UNC 路径，实际 Mac 原稿无法提交。补齐 POSIX 中文路径，保留 POSIX 文件名大小写差异，防止两个文件的字体设置合并。
3. 缺少标准 Mac 应用菜单，首页抢占 Cmd+H。增加应用/编辑/窗口菜单；Cmd+H 留给系统隐藏；画布已有 Cmd+Z/Shift+Cmd+Z 处理继续使用。
4. 原 ICNS 直接铺满透明标志。新增复用品牌标志的图标生成步骤，1024px 中保留标准留白、深色圆角底板，并生成完整 1x/2x ICNS。
5. 高级审验在 860px 窗口横向溢出。调整 1000px 以下为单列并允许文件名收缩。
6. Adobe 未安装时缺少明确的调用前检查。使用 `open -Ra -b` 查询注册应用，未找到时在脚本提交前报告“原稿尚未修改”，不触发应用选择或盲目重试。
7. Windows 夹具盘符、大小写折叠、固定输出目录和过严的浮点几何断言造成 Mac 自动测试误报。改用平台适配夹具；Windows transport mock 与 Mac transport mock 分别覆盖原有结果契约，没有放宽生产路径校验。
8. 原封装 smoke 可能在 CDP 待答但无活动句柄时以 0 退出。新增 watchdog、CDP 超时、阶段日志；必须读取新生成的 rendererPassed 结果。

## 更新通道与发布边界

客户端固定 feed 为仓库 `releases/download/mac-updates/update-macos-arm64.json`；版本化资产使用 `mac-vX.Y.Z-arm64/Sparkit-X.Y.Z-Mac-arm64-Setup.pkg`。协议2要求产品、darwin、arm64、pkg、签名、长度/哈希与策略序号，拒绝 Windows ZIP。

`tools/prepare-mac-update.cjs` 在 Mac 上读取仓库外的 options JSON，先验证 PKG 的 Developer ID Installer 签名及系统安装信任，再生成独立签名清单和完整包。私钥路径在 options 中指向仓库外；工具不打印密钥、不发布、不修改 Windows latest。`services/macos-release-publisher.cjs` 的测试使用一次性夹具密钥，成功路径中的 Apple 校验由夹具替代，不能当作生产签名证明。

尚未公开启用 Mac feed（本轮只读请求 HTTP404），也未发布可信签名的正式升级包。Windows 正式 latest 经查询仍为 v0.3.107。真实签名、公证后的“检查→下载→系统安装→版本变化→重开”成功链路仍需 Apple Developer 证书和公证条件；当前只证明协议、传输、安装交接夹具和不可信包拦截。

## 复测命令与 GUI 会话

所有本机调用显式使用 `C:/Program Files/PowerShell/7/pwsh.exe`、`login=false`。先读 `G:/无限画布/docs/Mac远程连接与测试手册.md`，复用 SSH 别名和密钥。以下路径均为本任务专属目录：

```powershell
$r = '/Users/jingchun/CodexTests/sparkit-mac-20261126-125143'
$node = "$r/packages/node-v24.11.1-darwin-arm64/bin/node"
ssh -o BatchMode=yes infinite-canvas-mac /usr/bin/sw_vers
ssh -o BatchMode=yes infinite-canvas-mac $node "$r/source/tools/mac-remote-qa.cjs"
ssh -o BatchMode=yes infinite-canvas-mac $node "$r/source/tools/mac-update-transport-qa.cjs"
```

注意：第二条综合入口直接 SSH 会话中的钥匙串集成可能失败。真实原生套件通过本任务 LaunchAgent 进入 `gui/501` 执行，label 为 `com.sparkit.qa.sparkit-mac-20261126-125143`；任务 plist 位于 `tmp/qa-agent.plist`。安装包 smoke 和生命周期分别使用 `.package.`、`.lifecycle.` label。仅重建/卸载这些本任务 label，不操作别的分支任务。正式应用没有 LaunchAgent 常驻要求。

通过 `sandbox-exec` 再包裹 Chromium 会导致其子进程无法建立自己的沙箱，GPU/网络服务崩溃。该失败已记录，最终 smoke 使用仅作用于被测 Chromium 的无效 loopback 代理，保留 Chromium 自身沙箱；查看 `chromiumProxyBlocked` 字段。不要禁用系统 Gatekeeper、移除隔离标记或给运行中的用户软件改代理。

任务收尾卸载以上3个任务 LaunchAgent，保留 plist、隔离数据、测试命名空间和日志供续测。其他分支进程与任务未停止。
