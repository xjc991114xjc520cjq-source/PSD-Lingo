# SKU 底部模板替换（本地开发功能）

状态：软件执行链已接入；本次客户稿和 Adobe 实机验收暂停。没有发布更新。不能将自动回归或成功构建当作客户成稿通过。

## 使用入口

AI 助手使用当前绑定的本机 Codex。附加原稿 PSD/PSB、产品 XLSX、独立模板 PSD/PSB，选择输出目录并说明替换范围、清理对象、跳过产品及排版要求。

1. `match_product_boards` 建立当前原稿与表格的对应。用户在产品对应面板批准；换文件、画板或表格后旧批准失效，不能套用别的路径上的旧决定。
2. `import_source`、`import_product_mapping` 导入同一原稿和批准字段。
3. `inspect_product_template` 读取对象结构，返回 `scanId`，不改原稿，首页同时提供已校验的小尺寸模板参考图。支持按 `boardId`、`offset`、`limit`（最多 100）分页。源稿跳过画板不深入；模板只读深入嵌入 PSD/PSB。
4. `configure_product_template` 一次说明旧块对象、对应模板、清理对象、每产品价格和位置；完整覆盖采用画板，跳过画板不传。配置进入撤销历史和项目持久记录。
5. `preview` 生成独立可编辑副本；`export_files` 复用副本、另存、重开及导出所有画板 JPG，通过现有多技能设计审验链评估实际最终画面。发现问题修改计划后再生成，不反复运行未变化的失败计划。

整块替换与原位改字是两个入口：只修改已有文字用 `configure_product_copy`；导入新模板并清理优惠子区用 `configure_product_template`。不能叠加未撤回的普通文字／对象修改。

## 替换计划

顶层参数：`scanId`、`templateRootId`（扫描返回的分组或嵌入 PSD/PSB 对象）、`templateFrame:[x,y,w,h]`（模板参照框）、`outputFormat:auto/PSD/PSB`、`documentName`。

- `templateFields:[{field,objectIds}]`：表格每个字段对应模板金额文字对象；不同字段不得共用同一对象。
- `removeObjectIds:[id]`：明确移除的模板标签、金额、减号等对象。缺失／斜杠字段的金额不能保留模板示例值，标签和分隔符也要按需求清理。
- `layout:[{objectId,x,y,anchorX,anchorY}]`：以模板原生坐标设置可见字形锚点，锚点取 0、0.5、1。父子对象不能同时位移。嵌套智能对象须加 `coordinateSpace:object-document`，使用返回的 `localBox` 和 `nativeCanvas` 所在文档的局部坐标，不能把全局位置直接传入子文档。此数据用于执行，不能代替图面的视觉审验。
- `boards:[{boardId,replaceRegion,oldObjectIds,reason,placement,changes,fieldExclusions}]`：全部采用画板一次配置。`replaceRegion` 为画板内相对范围；`placement` 为原稿绝对坐标的模板参照框，只允许等比缩放。旧块必须属于本画板，不能删除画板或超出授权区域；原已越出画板边缘的装饰按画板内可见部分核对，不把旧溢出误判成本次错误。
- `changes:[{objectId,original,recordId,recordSlice?,prefix?,suffix?,spans?,anchor}]`：价格只能来自本产品本字段的批准记录；分离整数／小数时，所有切片恰好覆盖一次。前后缀只允许模板原有货币及标点。混合字形必须明确 `spans:[{text,sourceStart}]`，继承货币与数值各自的原生字符样式。
- `fieldExclusions:[{recordId,reason}]`：仅用户明确排除的有效字段，必须说明依据并移除对应模板金额对象；不能用它默默漏掉价格。

每个画板可覆盖通用 `removeObjectIds` 和 `layout`。不含客户具体名称、价格或模板对象硬编码，替换别的项目仍从其真实对象和批准表格重新建立计划。

## 正式后台调用入口

`services/sku-product-template-engine.cjs` 是助手和后台共用执行服务；`services/sku-template-background.cjs` 是 Electron 无窗口入口。后台调用只做软件的结构检查与原生生成，**不自动获得设计通过**。

PowerShell 示例（路径按本机环境替换，命令本身不启动客户任务）：

```powershell
& '<Electron可执行文件>' '<源码目录>/services/sku-template-background.cjs' '<绝对路径>/job.json' '<绝对路径>/新的result.json'
```

job 公共字段：`action:inspect/configure/run`、`sourcePath`、`templatePath`、`mappingDirectory`（软件已批准产品对应的本机目录）、`mappingId`、`cacheDirectory`；以上目录及文件路径均为绝对路径，可选 `helperPath`。

- inspect：可带 `page:{boardId,offset,limit}`，结果为分页对象和扫描 ID。
- configure：带 `args`（上节替换参数和 inspect 得到的真实 scanId），结果为 `plan` 与 `artboards`。
- run：带 configure 返回的 `plan` 和全新的 `outputDirectory`。拒绝覆盖已有输出目录／结果 JSON，计划和文件失效则停止。错误后可能留下空输出目录或未验收的工作副本，不自动当作可交付结果。输出返回副本、JPG、文件摘要与原生重开验证；之后还须进行最终画面审验。

缓存仅保存结构 JSON，不把巨型源文件复制进学习库。源稿、模板、批准摘要、价格字段或计划内容变化均重新校验。缓存损坏直接报错，不改成静默重扫并盲目重试。

## 当前边界

支持原稿的顶层原生画板、普通分组／文字／像素对象，以及模板内嵌入的 PSD/PSB 智能对象（最多六级）。链接对象、AI/PDF/EPS 等模板智能对象明确拒绝，不能悄悄栅格化。旧块删除作用于原稿原生对象，嵌在智能对象中的旧底部块目前需选择其整个外层对象，不能假装已支持任意内部块删除。

模板中的原生画板导入为普通可编辑分组，导入的是画板内对象，不将外部画板本身嵌入原稿；画板背景设置不是独立素材。每产品独立复制模板，编辑智能对象时隔离实例。保留产品图、原画板名称与位置及跳过画板；是否达到最终设计要求仍由真实 JPG 证据判断。

## 表外画板删除（批准后，仅输出副本）

产品对应确认支持三种不同决定：`use`采用、`skip`保留但不修改、`delete`从输出副本删除。删除选择必须带`deleteConfirmed:true`及明确依据，绑定进批准摘要；不能把跳过或未匹配自动当作删除。

配置模板时传`deleteBoardIds:[原生画板ID]`，清单必须与当前批准的所有delete决定完全一致。源稿变化、批准范围变化或清单缺少／多出画板均拒绝执行。只有代表画板范围的批准不能授权删除完整稿其他画板。仍需为全部use画板配置底部模板。

执行先解析全部原生引用，完成保留画板的模板替换后再删除批准画板，防止兄弟层索引移动导致错删。保存重开只验收和导出剩余画板；保留及skip画板维持原名、原坐标。原稿不删除。普通原位改字入口拒绝带delete的批准，必须走模板配置流程。

Windows桥接JSON输入输出明确采用UTF-8，中文输出目录与英文目录使用同一入口。`validate-photoshop-script`仅校验路径及扩展名，不调用Adobe，供编译程序回归；完整原生执行另需实机验证。

### 模板容器与进度补充
实机英文路径进入原生执行后无后续输出，尚未判定死锁。代码核查发现活动画板可能收纳新建组，而动态遍历该画板子层存在自包含风险。现先快照原有子层，再将新组显式移至原画板前并要求Document父级；复制次数由原有清单固定，禁止复制容器自身。模拟回归覆盖自动收纳和复制期间集合增长，实际Photoshop仍待验证。

新脚本将阶段写至输出目录native-progress.json，含对照图序号、模板副本、字段、逐子层导入、保存、重开和最终JPG。可在该任务目录创建cancel.request请求协作取消，须等待脚本到达下一检查点并完成finally清理；不能打断正在进行的Adobe原生调用，不能保证旧脚本取消，不能把杀后台进程视为Adobe已停止。

### 无画板组装与诊断
画板模板的子层先在独立无画板临时文档组装，按原生ID选中后建立普通组，核对原层序、位置和文字样式后再导入目标画板。临时合并底层会删除，最终文字/分组/智能对象保持原生可编辑。此路径避免依赖Photoshop将新组保持在活动画板外，以及DOM逐层移入组的行为。
输出目录同时记录native-progress.json（当前阶段）及native-progress.jsonl（阶段历史、elapsedMs与必要对象上下文）。它们是本机诊断文件，不进入学习库或云端。独立原生回归入口为tests/sku-template-import.native.cjs，需当前Adobe空闲许可及显式测试环境变量；不能在普通自动测试中隐式运行。

跨文档复制可能落入错误的活动画板；软件按来源图层ID和指定目标画板的原生索引重挂接，核验实际父级后继续，不以活动画板替代目标。独立原生入口设置SPARKIT_TEMPLATE_MULTI=1可验证此情形。多画板保存会重算文字textClickPoint百分比，模板审验以绝对可见位置与字符样式共同核对，不将该百分比单项变化当作字体错误。

## 默认价格项减少合同（内置软件，不依赖学习服务）

仅要求“按表替换”时，助手也须从本次模板实际图像与原生对象识别`priceGroups`，无须用户重复要求清理和重排。每组结构为`{containerId,axis:"horizontal"|"vertical",items:[{field,objectIds}],separators:[{objectId,leftField,rightField}],preserveObjectIds?}`。`objectIds`选本字段完整阅读组（标签、货币、金额等，允许独立父组），不能跨另一个字段。主到手价单独一组／容器，不能混入价差组；`preserveObjectIds`仅声明该容器中不参与价格的标题／型号等，不允许借此保留孤立运算符。

该映射属于助手对当前模板的一次语义规划，不是新用户必填项。角色／运算关系确实有歧义才澄清。任何减少字段却缺少语义声明、未归属标签或符号的计划均拒绝配置，并返回具体补充要求。旧版有减少项的计划需要用原缓存补语义后重新configure，不必重复全稿分析。

编译按每个产品的批准字段分别判断缺失（空白／斜杠等非value）或用户明确排除项，自动生成整组删除与失效连接符删除；有效数值0保留。仍有两侧有效字段的符号不得删，产品型号内连字符不作为运算符。规划不能只移除示例金额留下标签。

没有完整显式布局覆盖时，执行在真实改字、删除之后读取剩余阅读组可见边界，保持组内标签与金额相对关系、原字符样式和跨轴位置，在原阅读范围内平均分配剩余空白；单组居中，有效分隔符放到相邻阅读组之间。不按字符框打视觉分，不拉伸、不统一字号。内容／运算符放不下时返回明确布局缺口。不同容器分别执行；嵌入PSD/PSB的内层分组使用其自身文档局部坐标，不跨容器计算。

用户显式布局优先，但减少项所在组须覆盖全部剩余阅读组与有效符号，局部覆盖不冒充空槽已回收。所有自动动作、语义摘要与原始决策进入同一可撤销计划、保存恢复和主进程重编译验证。改变模板、批准字段或角色时重算；最终JPG仍审验层级、可见间距、主价、孤立符号、空槽及新遮挡，结构通过不代表用户视觉批准。

独立原生验证：`SPARKIT_ADOBE_TEST=1`（获得当前空闲许可后）运行`tests/sku-price-reflow.native.cjs`，可用`SPARKIT_PRICE_EVIDENCE`指定全新输出目录。只创建小样，验证三到二／一及不同缺失项、有效0、保存重开与JPG，不重新处理客户原稿。

## 按产品替换赠品（单模板，当前本地能力）

产品对应字段增加 `role:"gift"`，手动面板可写 `赠品=E:gift`；该列保留工作表、单元格及批准摘要，不导入为普通价格文案。空白／斜杠赠品表示没有赠品，移除示例赠品及其专属徽标；价格占位符的保留规则不能让旧赠品沿用。不同工作表不能未经确认互借内容。

把本次PSD/PSB模板和PNG目录都附加到当前助手任务。`inspect_product_gifts({fileId})`只读检查目录，按完整名称匹配PNG，规范化空格、大小写和引号，不模糊猜型号、颜色或数字。支持 `名称 价值99元+名称 价值69元`，不会拆开型号自身的加号。当前要求赠品价值明确；不能解析的赠品描述、缺图或重名需先解决，不能假装完成。

`inspect_product_template`返回模板原生结构；未统一成顶层组的PSD可选择虚拟根`@document`，不要求用户先手动整理。助手依据本次实际模板映射`gifts`：

- `field`：批准的赠品字段；`directoryFileId`：本任务目录附件ID，路径由主进程解析。
- `containerId`：可独立重建的赠品内容组；`textObjectId`：组内同文档文字原型。
- `textParts`：`{token:"name"|"value",sourceStart}`或`{text,sourceStart}`，继承原型分段字体。常量必须确实来自指定原文位置，不能加营销主张。
- `frame:[x,y,w,h]`：赠品阅读区域的当前文档局部坐标；`axis:"horizontal"|"vertical"`。
- `imageFrame`、`textFrame`：每个赠品单元内的相对区域（0至1），不重叠；`textAnchor:"left"|"center"|"right"`。默认按图文组合的整体可见边界在单元内居中；用户要求严格保留槽位时可显式`unitAlignment:"slots"`。
- `emptyRemoveObjectIds`：没有赠品时要同步移除的专属徽标／分隔线。不能覆盖价格或产品主图。

这些映射由助手分析本次模板后配置，不是按历史客户ID或固定像素套用。单／多赠品均创建独立原生组与嵌入式图像，按实际数量安排单元，读取实际可见内容进行等比缩放及居中；文字保留原型字形，不擅自压缩、截断。空间不足须调整本次整体区域后再执行；单产品最多12项，配置时提前检查。

`configure_product_template`将价格、赠品、旧块清除一次编成同一可撤销计划。赠品区与价格／删除／布局发生父子重叠则拒绝；无赠品清理去重。预览和导出前后均校验目录内容哈希，保存／恢复后重新编译；输入变化需重新配置，不能沿用旧赠品。已有手动／助手历史记录保存该计划及目录引用，不复制PSD或PNG进学习库。

最终JPG审验同一次请求附带本产品预期PNG的小型透明裁切参考图、完整名称及价值，检查数量、款式颜色、等比形状、文案及间距；小图不作为当前完成画面。此处不新建额外模型会话。原生保存重开检查和设计审验仍是两项不同证据，不能用框值或哈希冒充美感通过。
