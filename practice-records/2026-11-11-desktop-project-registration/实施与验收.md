# 首次桌面项目注册与助手归属

## 问题与范围

需求：新电脑首次使用助手时，在软件配置的名称/目录建立真实 Codex 桌面项目；后续助手任务复用。已有后台 projectId 不等于桌面已注册。只处理软件助手任务，不移动开发、修复、设计聊天，不直接写 Codex 私有状态。

## 实现（基于 0.3.65，尚未发布）

- AgentProject.prepare 先用只读桌面项目根目录及本机 host 映射确认注册；过期、仅后台存在的编号不能绕过。
- 缺少注册时用官方 codex://threads/new?path=<encoded absolute directory> 入口，由桌面自身完成项目创建、目录确认、缓存、编号映射和通知。不发送提示词、不启动额外模型。
- 注册完成后 project/read 核对后台编号、目录，再调用原有 thread/start 并强制确认返回 projectId。
- 已注册路径直接复用，保留手动改名；优先保留仍有效的已保存编号。只持久化 Sparkit 自身配置；旧任务完成不会覆盖用户后来改过的目标。
- 首次等待最多90秒，可取消；目录未授权、协议缺失、映射不完整或后台不一致会明确失败，不建立项目外对话。再次开始复用桌面按路径去重。
- 不引入模型规划调用，不扫描整个后台项目分页。首次目录确认可能需要用户在 Codex 授权。只读注册格式依赖桌面当前版本，格式变更时需要适配，不能谎报支持。

## 继续验收：2026-11-11，用户恢复窗口后

前述待验项现已完成，并补了实际发现的桌面会话目录同步缺口：

1. 恢复窗口后首次测试对话实际位于新建项目下；无需修改后台编号。
2. 第二个同项目空白对话完成一次短本机回复后，后台归属正确，但当前桌面没有主动收到独立 app-server 的更新通知，侧栏仍未显示它。此前“后台归属正确”不能作为实时可见验收。
3. 新增 syncThread 收尾回调：一个新原生对话首次回合结束后，以 codex://threads/<uuid> 让桌面读取并登记这一条已持久化对话。通过生产 CodexDesktopProject.openThread + Electron shell 真实调用后，已看到项目下同时列出“Sparkit 项目归属验收（重复任务）”和“Sparkit 项目归属验收（短回复）”，页面打开的是重复任务且有真实短回复。
4. 同一会话后续追问不重复打开；新会话分别接收一次。桌面链接不含提示词/客户文件，不发送模型请求。收尾时会打开对应 Codex 对话页面，这是当前公开入口的可见行为，不宣称完全静默后台登记。
5. 该通知在首个已启动回合收尾运行，包括停止/失败后的可用会话；不会覆盖软件已完成的操作。链接失败记独立 desktop_sync_warning，不使已完成任务变成失败；后续追问允许再次尝试通知。
6. UUID 严格校验，禁止把自定义路径或 prompt 注入线程链接。只通知当前软件新建对话，不移动其他聊天，不修改旧项目迁移开关或私有数据库。

最终验证：737项 Node 回归、renderer 构建通过。新增测试覆盖首次回合后接收、追问去重、链接失败保留已完成改字结果与独立警告、非法链接拒绝。
