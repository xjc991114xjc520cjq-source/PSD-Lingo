# 按无限画布方案处理 Sparkit 首次启动

用户于2026-11-26要求仿照无限画布方案执行。只读参考：

- `G:/无限画布/mac-app/scripts/生成启动修复包.py`
- `G:/无限画布/docs/项目记录/Mac移植首版与启动修复-2026-11-26.md`

实际方案是版本绑定的定向下载隔离修复，不是 Apple Developer ID 签名或公证。本次明确要求适用于 Sparkit 测试副本；不是关闭系统 Gatekeeper，也不是对其他应用批量放行的授权。

## 实现与执行

`tools/mac-startup-repair.cjs` 从已校验原包的 Mac `.app` 生成自包含 `.command`、绑定清单和启动修复 ZIP。固定检查产品ID、内部版本、完整性签名及以下六个文件SHA-256：Info.plist、主程序、CodeResources资源封印、main.cjs、设备helper、内置Codex。所有检查通过后仅对传入的这一 `.app` 执行 `xattr -dr com.apple.quarantine`，随后再次验证签名。`--no-launch` 仅略过打开动作，仍会执行修复。

当前工具绑定5号测试包，原PKG SHA-256为 `6ab31a52853e1cc9d05153c23599f91a51bcae288ae1196b3224831346b582e9`。内部版本相同的其他测试包也不能混用，因为代码与封印哈希不同。

`package-macos.cjs` 已接入生成器，今后构建会自动附带对应修复 ZIP；当前5号包无需重新签名或修改，修复附件从原包直接生成。未修改正式更新器对PKG签名和系统信任的要求。
