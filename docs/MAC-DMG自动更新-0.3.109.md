# Mac DMG 自动更新 0.3.109

用户要求改用 DMG，解决截图中 `pkgutil --check-signature` 拒绝安装的问题。本版将自动更新改为完整应用替换，不调用 PKG 安装器。

## 迁移与分发

0.3.107/108 的已安装代码仅认识 PKG，服务器不能改变旧客户端的更新执行逻辑。因此首次需保存项目、退出旧版，手动将 0.3.109 DMG 中的 Sparkit.app 拖到 Applications 替换。之后的更新使用 DMG 自动更新。

DMG 通道为 `mac-dmg-updates`，清单仍使用产品已有的 ES256 信任公钥，协议 3、包类型 dmg、版本化文件名固定为 `Sparkit-<版本>-Mac-arm64.dmg`。保留旧 PKG 验证器和旧通道兼容，避免向旧客户端发送无法识别的新协议。Windows latest 不受此通道影响。

Mac 桌面交付目录为 `/Users/jingchun/Desktop/灵搭Sparkit-Mac-DMG-0.3.109`；不替用户关闭正在运行的生产应用，也未覆盖生产安装或用户项目。

## 执行流程

1. 验证发布者签名清单、固定 URL、版本策略、完整下载长度及 SHA-256，验证 DMG。
2. 只读挂载，检查 Sparkit 标识、目标版本及完整深度代码签名，复制完整应用到安装目录内的唯一暂存路径。
3. 校验通过后，仅移除此暂存副本的 quarantine，再次验证签名。此步骤是用户授权的测试分发方式，不修改系统 Gatekeeper 策略。
4. 独立更新助手确认启动后，主程序才退出。助手等待原进程退出，重新检查身份、版本、资源封印和主程序哈希，再将旧应用备份、原子替换。
5. 清除助手的 Electron Node 模式环境后，通过 LaunchServices 打开新版。新版窗口加载完成后写入受限路径的启动回执。未收到回执时停止失败副本、恢复旧应用并打开旧版。

用户数据、项目文件和 Keychain 均不随应用替换。无写入安装目录权限或处于 AppTranslocation 时会保留当前应用并说明原因；不会静默申请管理员权限。
