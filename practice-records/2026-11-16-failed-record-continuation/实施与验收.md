# 失败工作记录恢复并继续

## 需求与入口

用户要求在旧失败记录内新增“恢复并继续”。入口：工作记录 → AI 助手失败／异常中断／终止记录详情 → 恢复并继续。现有“恢复并重新运行”保留。

## 实现

- 使用失败后的完整 after 工作区，而非 before。恢复进度立即显示，校验原稿与附件，备份当前工作区，恢复界面、参数、计划，再打开助手蒙版启动续做；重复点击不会排队启动。
- 以原任务完整结构化历史重建本机助手上下文，原需求、补充、问答、已成功和失败的工具调用均保留。不会自动重放历史写入。独立任务标记已准备，不再次清空恢复的画布。
- 续做前由软件只读读取 workspace，向助手提供恢复后的真实对象与计划。旧预览图不假装恢复；需要图像时重新预览。仍执行原有导出与审验门禁。
- 恢复顶层及授权文件夹内已发现附件的原始 ID，校验实际路径、类型、大小与修改时间；不把历史 ID 替换成失效新 ID，不扩大目录权限。
- 恢复校验后的单次、记录绑定凭据，防止未恢复工作区直接启动续做。扫描编号确因恢复重建发生变化时保留经校验的新旧映射；同文件同对象修复可消除旧错误，不掩盖其他错误。
- 原失败记录保持，续做使用新任务 ID 与关联工作记录。沿用原本机模型与项目配置，通过本机 Codex 建立完整上下文；不声称恢复同一底层 Codex thread 或模型缓存。

## 边界

- 没有失败后工作区快照的旧版记录无法安全断点恢复，按钮禁用并显示原因，仍可恢复需求重新运行。API 历史任务不能冒充本机续做。
- 文件移动或内容变化、输出目录不可写、当前有活动任务均不能启动。失效产品映射及运行时扫描仍须通过原软件检查重新确认，不猜 ID 或自动批准。
- 写入未回报或 uncertain 不等于未执行，完整证据传给助手并明确要求先核对已有输出，禁止盲目重试；不承诺模型永不提出重复动作。
- 不为本功能自动恢复或启动任何真实客户任务。不改客户原稿，不调用 Adobe、不控制桌面。
