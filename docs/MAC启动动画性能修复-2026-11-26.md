# Mac 启动动画性能修复

## 问题和修改

用户反馈候选5启动动画特别卡。检查发现自动播放以 requestAnimationFrame 逐帧暂停并 seek 全部 Web Animations，同时查询和改写 SVG/文字节点。高分屏还要合成4个超过窗口大小的渐变层、径向蒙版及 screen 混色。

改为一次建立动画轨道，用统一浏览器时间线直接播放；保留手动 seek、Esc/按钮跳过、减少动态效果、结束后恢复工作区交互。装饰轨道的曲线预先采样，不在播放期间写入 DOM。光效画布限制到最大960×720 CSS像素，复用渐变本身的透明边缘，去掉重复蒙版和全屏混色；轨迹SVG限制到640×400，并去掉轨迹阴影滤镜。Logo、文字、色彩和三秒整体节奏保留。

## 实机证据与边界

设备为 Apple Silicon MacBook Air，macOS26.0，DPR2；1440×784 CSS像素可见测试窗口。GPU合成、光栅化均开启，没有修改系统图形或安全设置。

- 旧版重播脚本耗时约94–109毫秒；修复后约7.5–8.4毫秒。重播布局次数由175–182次降至35次。
- 最终源码三次重播：各182个帧间隔，P95约18.1–18.2毫秒，最大约18.7毫秒，无超过34毫秒的间隔。
- 实际候选6通过 LaunchServices 启动，252个按钮、preload和首屏就绪；包内重播183个帧间隔，P95约18.4毫秒，最大18.7毫秒，无超过34毫秒的间隔。
- 源码初次页面加载，从dom-ready开始采样仍记录一次约100毫秒的长帧。中间方案首次重播也曾出现166–383毫秒间隔，因此不能仅以稳定重播结果宣称所有冷启动卡顿彻底消失。未稳定复现用户所述持续严重卡顿，最终体感待用户复测。
- 数据是 requestAnimationFrame 回调间隔与 Chromium Performance 指标，不是显示器实际呈现帧数或录屏分析。
- Mac/Windows首次绘制交接、加载失败回退、减少动态效果通过；Mac性能套件的自动结束、手动定位截图、Esc跳过和inert恢复通过。4项启动服务Node测试通过。
- impeccable静态检测无发现；已查看Mac实际截图，Logo与文字显示正常。
- 未调用外部模型、Adobe或真实账号数据。当前用户安装并运行的 `/Applications/Sparkit.app` 未改写或结束。
