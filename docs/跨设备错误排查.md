# 跨设备错误诊断

客户端遇到错误时，先写入本机诊断队列，首次约10秒后尝试批量同步，之后每分钟检查；上传失败指数退避，等待联网和有效授权。不会为日志调用AI或重跑设计任务。错误编号生成后即固定，可在“左侧工作记录下方的“错误上报””复制并查看待传状态。

上报字段限定为版本、设备签名、时间、任务编号、操作/阶段、错误代码、过滤后的错误与调用栈、近期步骤名称、Windows及Adobe版本、源文件格式/大小/指纹。不会上传源文件、画面、图层文案、任务提示词、模型对话、工具参数、登录凭据。客户端和服务器均执行固定字段契约。

用户反馈另一台电脑的问题时，开发排查应先查询云端诊断；优先用错误编号，没有编号时按设备、版本、任务或错误代码筛选。不要仅凭截图认定源文件损坏。查询需管理员权限，普通客户端不能读取其他设备的记录。

## 开发查询

`node server/tools/query-diagnostics.cjs --login-file 本机私密目录/admin-login-proof.json --id 错误编号`

也可使用 `--version 0.3.95`、`--device win-…`、`--task 任务编号`、`--code 错误代码`。不带筛选查最近30条，返回nextCursor，可用--before和--cursor翻页。凭据文件包含管理员email/passwordProof，放在仓库之外，绝不粘贴到对话或上传。现有管理控制台也有“跨设备错误诊断”查询及详情入口。

## 容量与失败边界

- 每批最多8条，每条约8KB以内；重复错误10分钟内合并并累计次数；本机最多500条、保留30天。
- 每设备每天最多50次云端记录写入，全服务诊断每天最多1000次，客户端每天最多100次批量请求；额度耗尽等待UTC次日，不影响本机制图。
- 云端独立表与诊断预算，保留30天，并按小时分批清理超过20000条的旧记录。最高载荷约160MB，索引另计；全服务授权/学习库仍共享数据库底层容量，定时上传不能绕过服务商免费额度。
- 云端未确认的记录不标为已上传。上报失败只影响诊断同步，不应中止导入、制作或导出。
- 旧客户端此前没有上传的本地错误不会凭空出现在云端；更新后再次出现的问题才可自动调取。主进程崩溃先保留最小本机摘要，下次启动后续传。

部署顺序：备份/本机测试 → 应用0008迁移 → 部署Worker并保留现有变量/密钥 → 真实设备签名上报与管理员查询验证 → 客户端验签发布。云端和客户端均验证后才可宣称跨设备链路可用。
